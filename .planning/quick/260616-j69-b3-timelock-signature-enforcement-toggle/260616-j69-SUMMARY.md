# Phase quick-260616-j69 Plan 01: B3 Signature-Enforcement Disable Timelock Summary

**One-liner:** 48-hour two-step timelock (propose/execute) protecting the signature-enforcement disable path in spot_settlement, with immediate re-enable preserved.

## What Was Built

Closed P0 blocker B3: a compromised owner key could previously disable ECDSA signature
verification in a single transaction. The fix gates `set_signature_verification_enforced(false)`
behind a mandatory 48-hour timelock implemented as a propose → execute two-step flow.

### Production changes (Lunex/contracts/spot_settlement/lib.rs)

1. **SpotError variants added:**
   - `EnforcementTimelockNotExpired` — returned by direct `set(false)` and by `execute` before deadline
   - `NoPendingEnforcementDisable` — returned by `execute` when no proposal is active

2. **Storage fields added** (appended after `attestor_pubkey` — safe in ink! 4.x):
   - `pending_enforcement_off: Option<u64>` — deadline timestamp (ms), `None` = no proposal
   - `enforcement_timelock_ms: u64` — initialised to `48 * 3_600_000 = 172_800_000`

3. **Constructor updated:** both fields initialised (`None`, `172_800_000`).

4. **`set_signature_verification_enforced` gated:** the `false` branch now returns
   `Err(EnforcementTimelockNotExpired)` immediately (owner check still runs first);
   the `true` branch (enable) remains immediate.

5. **Four new `#[ink(message)]` methods:**
   - `propose_disable_enforcement()` — owner-only; sets deadline = now + 172_800_000
   - `cancel_disable_enforcement()` — owner-only; clears `pending_enforcement_off`
   - `execute_disable_enforcement()` — owner-only; enforces deadline, sets enforced = false, emits event
   - `pending_enforcement_off() -> Option<u64>` — getter

### Test migrations

- `create_contract()` helper: replaced `set_signature_verification_enforced(false)` with
  `propose_disable_enforcement` + `set_block_timestamp(172_800_001)` + `execute_disable_enforcement`
- `test_owner_can_disable_enforcement_and_event_is_emitted`: migrated to two-step flow;
  event count assertion preserved (+1 for execute only; propose emits nothing)
- `test_non_owner_cannot_change_enforcement`: no change required — `ensure_owner()` still
  fires before the `!enforced` guard, so non-owner gets `AccessDenied` as before
