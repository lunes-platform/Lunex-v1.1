# Quick Task 260617-jz6 — B4: Factory wires fee/rewards routing into new pairs

## Problem (blocker 02-factory-revenue-bug)

`factory.create_pair` registered every new pair with `protocol_fee_to = None`
and `trading_rewards_contract = None`. Result: pairs created through the factory
collected **no** protocol fees and never notified the trading-rewards contract —
a silent revenue-loss bug. Fixing each pair after the fact required a manual
per-pair admin call that nobody made.

## Tasks

1. **fix(factory)** — Add factory-level `protocol_fee_to` / `trading_rewards_contract`
   globals (admin-gated setters/getters), and have `create_pair` wire them into
   each new pair atomically (fail with `PairSetupFailed` before `register_pair`).
   Includes 3 ink unit tests. *(verify: `cargo test` 13/13; `cargo contract build` OK)*
2. **fix(deploy)** — `deploy-contracts.ts` sets both globals after the rewards
   contract is deployed (Step 7) so locally-deployed pairs are routed.
3. **test(onchain)** — Add `prove-b4-factory-fee-routing.ts` (proof script).
   Run is DEFERRED (dev stack down) — committed for the later on-chain proof.
